# CtxSlim v0.5.0 — Design Spec (disclosure + images + tune)

Date: 2026-09-08. Status: approved by user in brainstorming; precedes implementation plan.

## Goal

Cut the remaining ~9k/request definition floor (~70% via opt-in disclosure),
shrink image-heavy tool results without costing agent capability, and turn
accumulated usage/stats/audit data into actionable config suggestions — all
without removing any tool power.

## Non-goals

- `--apply` config writing (tune is suggest-only).
- Auto-expand on blind tool call (rejected: wastes a call per tool).
- Image stripping or video/PDF handling.
- Changing default behavior for existing users (both proxy features are opt-in).

## Architecture

Three independent features behind two opt-in config knobs and one read-only
CLI command. No changes to upstream connection management, ranking, or
persistence formats.

## Components

### 1. Progressive disclosure (`slim.disclosure?: boolean`, default false)

When enabled, `exposedTools()` emits stubs instead of full definitions:

```json
{ "name": "<exposed>", "description": "<first ~120 chars of compressed description>", "inputSchema": { "type": "object" } }
```

- Stub descriptions reuse the existing `compressTool` description pipeline,
  truncated to ~120 chars (same `truncateWords` helper).
- New `describe_tools` meta tool: `{ tools: string[] }` → full COMPRESSED
  schemas (same pipeline as `search_tools` hits) for exactly the named tools
  (resolved exposed names). Unknown names are reported per-item, not errors.
- `search_tools` results already carry full compressed schemas; documented as
  the discovery path alongside `describe_tools`.
- Calling a stub-listed tool directly works unchanged: routing is by exposed
  name and the proxy retains full schemas internally. No fetch-before-call.
- Meta tools (`search_tools`, `describe_tools`, `enable_tools`,
  `list_servers`, `slim_stats`) always render full definitions.
- `tokensAfter`, banner, and `slim_stats` measure stub sizes (honest: stubs
  are what rides requests). `slim_stats` gains a `disclosure` boolean.
- Omitted or `false` preserves current behavior exactly.

### 2. Image downsampling (per-server `images`, absent = off)

```json
{ "mcpServers": { "browser": { "command": "...", "images": { "scale": 0.5, "format": "jpeg", "quality": 70 } } } }
```

- Applies to `image` content items (`{ type: "image", data, mimeType }`) in
  tool results: base64 decode → resize by `scale` → re-encode as
  `format`/`quality`. Non-image items untouched.
- Engine: OPTIONAL peer dependency `sharp` (`peerDependencies` +
  `peerDependenciesMeta.optional`), lazy `import()` only on the first image
  result from a configured server. Default installs gain no dependency.
- Configured-but-missing engine: loud stderr warning + original passes
  through (fail open — capability is never reduced by a missing dep).
- No removal path exists: images are transformed or passed through, never
  stripped. Validation rejects `scale <= 0` / `scale > 1` / bad enum with the
  same invalid-config error style as `output.maxChars`.
- Audit `outChars` meters post-processed bytes (consistent with the
  `output.maxChars` precedent). Stats-gating unchanged.

### 3. Auto-tune (`ctxslim doctor --tune [--json]`)

Read-only analysis over whatever of `usage.json`, `stats.jsonl`,
`audit.jsonl` exists; each section degrades to "no data" independently.
Deterministic rules (thresholds documented in `--help` and README):

- Usage count ≥ 5 and tool not pinned → suggest `pins` entry.
- Top-K called tools cover ≥ 90% of calls with K < `maxTools` → suggest
  lowering `maxTools` to K; distinct called tools > `maxTools` → suggest
  raising.
- Servers with zero calls across all data → "consider `exclude: [\"*\"]`"
  (worded as consideration, never a directive — unused historically does not
  mean unneeded).
- Tools with average `outChars` > 8000 in audit data → suggest
  `output.maxChars`.
- Mean definitions/request (`tokensAfter`) above 6000 with disclosure off →
  suggest enabling `slim.disclosure`.
- Never writes config. Human sections + `--json` mirror.

## Error handling

- Disclosure: `describe_tools` with empty array → usage error result (same
  style as `enable_tools`); unknown names listed as missing, call still
  returns 200-style result envelope.
- Images: invalid config rejected at startup validation; missing engine warns
  + passes through; per-image transform failure warns + passes that image
  through (never fails the tool call).
- Tune: missing files → per-section "no data" lines; corrupt audit lines
  reuse the existing skip-and-count tolerance.

## Testing

- Disclosure: stub shape/tokens vs full; describe_tools batch incl. unknown
  names; stub-listed tool still callable; meta tools stay full; off-by-default
  unchanged behavior; `slim_stats` disclosure flag.
- Images: transform math via stubbed engine interface (no sharp in tests —
  inject a fake resizer); missing-engine fail-open; invalid config rejected;
  non-image items untouched; audit measures post-processed bytes.
- Tune: rule coverage on synthetic usage/stats/audit fixtures; empty-data
  states; `--json` shape.

## Decisions locked in brainstorming

- Opt-in disclosure (`slim.disclosure`), default off — zero behavior change
  for existing users.
- Fetch via `describe_tools` + `search_tools`, never auto-expand on call.
- Images opt-in per server, optional peer dep, fail open, never strip (hard
  user rule: capability loss vetoes the feature).
- Tune suggests only; `--apply` is future work.
- Release as 0.5.0 minor with per-feature tests and README docs.
